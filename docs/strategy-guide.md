# 策略作者指南

> **本项目不提供任何策略、信号或投资建议。** 这里的示例只演示"怎么接"，不是能赚钱的策略。合约交易可能亏掉全部保证金；用不用、怎么用、是否符合你所在地区的法律，由你自己判断和负责。

这份指南写给想把**自己的**策略接进来验证的人：量化规则、机器学习模型、大模型（AI）策略、TradingView 指标都行。

**现状（2026-11-10）**：Webhook、qsig/1、回测、和币安对齐的模拟盘、币安实盘已经能用。验证报告、模拟和实盘对照、给策略单独设资金上限、和币安一样的接口正在做，做好后这份指南会更新。

## 一、这里能帮你做什么

你的策略留在你自己的程序里跑，只把"要做什么"告诉平台。平台负责：

- **同一套撮合代码**：回测、模拟盘、实盘走的是同一个撮合引擎，只换最后的执行通道。回测里怎么算手续费、强平、资金费，模拟盘和实盘就怎么算。
- **模拟盘可信**：规则逐条对齐币安 U 本位合约（价格和数量限制、保证金分档、强平和清算费、市价单保护、条件单、资金费按真实结算），还可以模拟你所在地区的下单延迟。对不上的地方写在文档里，不装作一样。
- **每一步都能查**：每条信号什么时候发出、什么时候到交易所、成交在哪、为什么被拒，全部记录，能复盘、能导出。
- **验证报告**：收益、回撤、对照组、成本提高后的结果、信心校准，门槛你自己定（见第四节）。

## 二、适合接什么样的策略

| 适合 | 不适合，以及原因 |
| --- | --- |
| 币安 U 本位永续合约 | 现货策略：现货只有模拟盘，没接实盘 |
| 持仓从几分钟到几周 | 高频、做市：平台不模拟排队位置和大单冲击，延迟是几十到几百毫秒 |
| 趋势、动量、均值回归、轮动、事件驱动 | 跨交易所套利：实盘只接了币安 |
| 大模型读新闻、读数据后给出判断 | 期现套利：要现货腿 |
| 按"目标仓位"或"开多 / 平仓"表达的策略 | 期权 |
| 一个或几个品种，或者一篮子币 | 要逐笔数据驱动的超短线：平台的回测只有 1 分钟 K 线 |

## 三、三种接法怎么选

| 接法 | 你要做的 | 适合 |
| --- | --- | --- |
| **A. TradingView 警报 / Webhook** | 往一个网址发"做多 BTC 30%"这样的一句话或 JSON | 不写代码；TradingView 上已经有指标或策略 |
| **B. qsig/1 目标仓位** | 定期告诉平台"每个品种应该持有多少"，带上理由和信心 | 程序化策略、AI 策略、多品种组合 |
| **C. 和币安一样的接口** | 你现有的币安程序、ccxt、Freqtrade、Hummingbot，把地址换成你部署的平台、换一把模拟密钥 | 已经有能对币安下单的程序 |

三种接法进的是同一个撮合引擎，验证报告也一样。

### A. TradingView 警报 / Webhook

在"账户 → TradingView 警报和 Webhook"新建一个地址，选它绑哪个账户（模拟或实盘）。

```
做多 BTC 30%
做空 ETH 20%
平仓 BTC
{"action": "long", "symbol": "{{ticker}}", "size": "30%", "id": "{{timenow}}"}
```

- 大小是**可用资金的百分比，按名义金额算**：30% 就是用可用资金的 30% 买这么多价值的合约，杠杆只影响占用多少保证金。
- `id` 可选，同一个 id 只执行一次，防止重发。
- 完整写法和发送示例见 [strategies.md](strategies.md)、[examples/webhook_send.py](examples/webhook_send.py)。

### B. qsig/1 目标仓位

qsig/1 发的不是买卖动作，而是"每个品种应该持有多少"：`weight` = 目标仓位的名义价值 ÷ 组合净值，带符号（正多负空，0 空仓）。平台把目标和当前仓位比，差额下单；止损止盈、熔断由平台执行。

为什么推荐用目标仓位：
- **不怕丢消息、不怕重发**：重复发同一个目标等于维持现状；漏了一条，下一条会把仓位拉回目标。
- **好验证**：平台能逐条比较"你想要的仓位"和"实际做到的仓位"，滑点和没成交的部分一目了然。
- **AI 策略友好**：每条信号带理由、证据、信心（confidence）、推理花费（cost_usd），平台展示、做信心校准、把推理成本算进净收益。

怎么开始：
1. "账户 → 我的策略 → 新建"：起一个策略名，拿到 key id 和 secret（只显示一次，要二级密码）。建好马上能用。
2. 把 [examples/qsclient.py](examples/qsclient.py) 复制到你的程序旁边：`Client().target({"BTC-PERP": 0.2}, reason="...", confidence=0.6)` 发目标，`wait(id)` 拿执行回报，`heartbeat()` 发心跳。只用 Python 标准库。
3. 每条消息都进这个策略的**前向记录**（哈希链）：策略页"下载前向记录"，用 [examples/verify_log.py](examples/verify_log.py) 验证。把链的最后一环发给要看你成绩的人，以后谁都改不了这之前的记录，包括部署服务器的人。

签名、心跳、错误码见 [qsig-1.md](qsig-1.md)。

### C. 和币安一样的接口

平台会把模拟盘包装成和币安 U 本位合约一样的下单接口和推送：签名、下单、条件单、仓位、成交、账户推送都一样。你的程序只改一个地址、换一把平台发的模拟密钥，就跑在仿真盘上；验证完把地址换回币安，就是实盘，代码不用改。支持的接口清单、ccxt 的改法、和币安不一样的地方见 [binance-api.md](binance-api.md)；没仿的接口会返回明确的错误。

## 四、推荐的验证流程

**1. 回测**（几分钟）：用历史数据检查逻辑、成本和最坏情况。
- 信号表每行"时间,信号"，写法和 Webhook 一样，见 [backtest.md](backtest.md)。
- **大模型策略的回测不可信**：模型训练时见过这段历史，回测会好得不真实。大模型策略只用回测检查"流程通不通、成本多少"，成绩看第 2 步。

**2. 模拟盘前向跑**（至少 30 天）：真实行情、真实规则，信号先记下、后看结果。
- **冻结版本**：考察期内改了策略，就从零重新计时。
- 模拟下单延迟选你部署服务器所在的地区（"账户 → 交易偏好 → 模拟下单延迟"）。

**3. 看验证报告**。默认门槛（可以自己改）：

| 指标 | 默认合格线 |
| --- | --- |
| 前向时长 | ≥ 30 天 |
| 已平仓笔数 | ≥ 100 |
| 扣费后总收益 | > 0，并且前半段、后半段各自 > 0 |
| 夏普（日收益年化） | ≥ 1.0 |
| 最大回撤 | ≤ 20% |
| 成本提高 50% 后 | 仍然 > 0 |
| 对照组 | 跑赢"一直拿着 BTC""同样换手的随机进出""简单动量" |
| 最赚钱一笔占总利润 | ≤ 25% |
| 信心有效 | 信心 ≥ 0.7 的信号比 < 0.5 的平均收益更高 |

胜率不在门槛里：低胜率高盈亏比的策略也可以很好。

**4. 模拟和实盘对照**（小资金）：同一条信号在模拟盘和实盘各执行一次，看两边差多少：成交价、手续费、成交时间、没成交的单。差得多，说明模拟盘的结果要打折看。

**5. 实盘**：给策略设资金上限和最大亏损；纪律锁和全局停机对实盘一样生效。

## 五、常见的坑

| 坑 | 怎么避开 |
| --- | --- |
| **未来函数**：用了当时还拿不到的数据（比如用这根 K 线的收盘价在这根 K 线开盘时下单） | 每个数据都问"它是什么时候才能知道的"；qsig/1 的 `data_as_of` 写你用到的最新数据时间 |
| **过拟合**：参数调到只适合这段历史 | 前一段调参数、后一段检验；最近几个月锁起来当期末考，只考一次 |
| **测太多次**：试了一千个想法，总有几个碰巧好看 | 记下你一共试了多少个；试得越多，门槛要越高 |
| **不算成本**：手续费、滑点、资金费 | 回测和模拟盘默认都算；看"成本提高 50%"那一行 |
| **忽略资金费**：持仓跨过结算时刻要付或收资金费 | 平台按真实费率算；持仓几天的策略，资金费可能比手续费还多 |
| **延迟**：信号发出到成交之间价格会动 | 回测设延迟；模拟盘选地区 |
| **样本太少**：十几笔交易什么也说明不了 | 至少 100 笔已平仓交易 |
| **大模型见过历史** | 大模型策略只看前向记录 |
| **改了版本不重新计时** | 改了就从零开始，旧成绩单独存档 |
| **只看收益不看回撤** | 先看最坏情况：最大回撤、最长回撤时间、单笔最大亏损 |

## 六、两个空模板

只有"怎么接"，没有"怎么赚钱"。

- [examples/qsclient.py](examples/qsclient.py)：qsig/1 客户端（签名、发目标、心跳、暂停、读执行回报和成绩）。下面两个模板都用它，复制到同一个目录。
- [examples/template_rule.py](examples/template_rule.py)：规则策略的骨架。定时取行情 → 你的规则算出目标仓位 → 用 qsig/1 发出去 → 发心跳。
- [examples/template_ai.py](examples/template_ai.py)：大模型策略的骨架。取数据 → 拼提示词 → 调你自己用的模型服务 → 检查输出 → 用 qsig/1 发出去，理由、信心、推理花费一起带上。
- 另外有一个能跑的演示：[examples/backtest_ma_cross.py](examples/backtest_ma_cross.py)（均线交叉生成回测信号表）。

## 七、大模型策略要特别注意的

- **把每次判断的原始记录留下**：用到的数据、提示词、模型名和版本、模型原始输出、发出去的 JSON、平台的回复，至少留 90 天。出了问题才查得清。
- **信心要校准**：模型说"有把握"的那些判断，实际赢得更多吗？验证报告会画信心校准图。说不准的信心只会误导你。
- **推理花费算进成本**：信号里的 `meta.cost_usd` 会被算进净收益。每 5 分钟问一次大模型、一次几美分，一个月可能上千美元。
- **限制模型能做的事**：仓位上限、杠杆上限、止损写在你自己的程序里，不要让模型的输出直接决定下多大；模型输出要先检查格式和范围，不对就不发。
- **温度和随机性**：同样的输入可能给出不同的判断。记下设置，必要时多问几次取一致的结果。
- **延迟**：大模型一次判断可能要几十秒。`data_as_of` 和 `issued_at` 之间的差会被统计；超过 10 分钟平台会提醒。

## 八、上实盘前的检查清单

- [ ] 模拟盘前向跑满你定的时长，验证报告全部过线
- [ ] 模拟和实盘小资金对照过，差距可以接受
- [ ] 交易所密钥只开了合约交易，没开提现和划转，绑了服务器 IP
- [ ] 账户是单向持仓模式
- [ ] 给策略设了资金上限和最大亏损；纪律锁开着
- [ ] 知道怎么一键停：账户页停掉策略，或者在"系统"页全局停机
- [ ] 断网、程序崩溃时会怎样：平台挂在交易所的止损照常有效；qsig/1 超过 180 秒没心跳会判定离线（仓位保持，止损照常）

## 九、我们不做的

- 不运行你的代码：策略留在你自己的程序里。
- 不保管你的钱：资金一直在你自己的交易所账户里，平台没有提现和划转。
- 不提供策略、不推荐策略、不承诺收益。

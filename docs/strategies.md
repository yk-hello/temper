# 接策略

先读 [策略作者指南](strategy-guide.md)：适合什么样的策略、怎么验证、常见的坑。这一页讲具体的接法。

三种接法，选一种就行。它们最后都走同一个撮合引擎，所以回测、模拟盘、实盘的结果能对得上。

| | 适合 | 下单方式 |
| --- | --- | --- |
| TradingView 警报 / Webhook | 已经在 TradingView 上写好策略；或者自己的脚本只想发"开多 / 平仓" | 动作 + 资金百分比，市价 |
| qsig/1 | 程序化策略、多品种组合、AI 策略 | 每个品种的目标仓位（权重），平台算差额下单 |
| 回测信号表 | 先在历史数据上验证 | 和 Webhook 同样的写法，外加完整委托 |

推荐的顺序：**回测 → 模拟盘跑一段 → 小资金实盘**。三步用的是同一种信号写法。

## 一、TradingView 警报 / Webhook

在"账户 → TradingView 警报和 Webhook"里新建一个地址，选它绑哪个账户：

- 绑模拟账户：在模拟盘成交。
- 绑交易所账户：单子发到你的币安账户（要先在"交易所账户"里开启下单）。交易所账户只接合约信号。

地址里的密钥只在创建时显示一次，丢了就删掉重建。

### 信号写法

一句话：

```
做多 BTC 30%
做空 ETH 20%
平仓 BTC
long SOL 10%
close BTCUSDT
```

或者 JSON（TradingView 里可以用 `{{ticker}}` 这类占位符）：

```json
{"action": "long", "symbol": "{{ticker}}", "size": "30%", "id": "{{timenow}}"}
```

- 动作：`做多 / long`、`做空 / short`、`平仓 / close / exit / flat`。`买入 / buy`、`卖出 / sell` 是现货。
- 币种：`BTC`、`BTCUSDT`、`BTCUSDT.P`、`BINANCE:BTCUSDT.P`、`BTC-PERP` 都认。
- 大小：可用资金的百分比，按**名义金额**算（30% = 可用资金的 30% 买这么多价值的合约，杠杆只影响占用的保证金）。新建地址时可以给它一个"资金桶"，百分比就按资金桶算。
- `id`：可选。同一个 id 只执行一次，防止 TradingView 重发。

发信号：

```bash
python examples/webhook_send.py "http://localhost:8080/api/hook/tv/<密钥>" "做多 BTC 30%"
```

信号照样过纪律锁和下单规则；每条信号的结果（成交、被拒和原因）在账户页的信号记录里。

## 二、qsig/1（程序化策略）

qsig/1 发的是"每个品种应该持有多少"，不是买卖动作。平台把目标和当前仓位比，差额下单；止损止盈、熔断由平台执行。

- 协议全文：[qsig-1.md](qsig-1.md)；Schema：[`protocol/qsig-1.schema.json`](protocol/qsig-1.schema.json)
- 密钥自己建："账户 → 我的策略 → 新建"，起一个策略名，拿到 key id 和 secret（secret 只显示这一次，要二级密码，需要部署的人配了 `QS_MASTER_KEY`）。建好马上能用，不用重启。也可以由部署的人写在 `QSIG_KEYS` 里。策略在"策略"页显示，用户可以在模拟账户上跟它。
- 签名：`HMAC-SHA256(secret, timestamp + "\n" + METHOD + "\n" + path + "\n" + body)`，小写十六进制，放在 `X-QS-Signature`；`X-QS-Key`、`X-QS-Timestamp`（毫秒）。
- 每 30–60 秒发一次 heartbeat；超过 180 秒没收到判定离线（仓位保持，止损照常）。

最小例子：

```bash
QS_BASE=http://localhost:8080 QS_KEY=my-key QS_SECRET=... QS_STRATEGY=my-strategy \
    python examples/qsig_send.py BTC-PERP 0.2
```

会打印接收结果和执行回报（实际达到的权重、成交均价、相对参考价的滑点、手续费）。

qsig/1 策略的目标仓位由平台换算成每个跟随者账户里的订单：跟随者可以选模拟账户，也可以选接好的交易所账户（开启要二级密码，分配金额、最大亏损、杠杆上限照样管着）。同一个策略可以同时有模拟账户和交易所账户在跟，两边的执行记录（成交价、滑点、手续费）可以对照。

### 前向记录：证明你的记录没改过

平台把每个策略收到的每条消息串成一条链：每条记下收到的原始字节、收到时间和上一条的指纹（`chain = sha256(上一条 chain + "\n" + id + "\n" + 收到毫秒 + "\n" + sha256(原始字节))`，第一条的"上一条"是空字符串）。改了任何一条（内容、时间、顺序，或者删掉一条），从那里往后都对不上。

- 下载：策略页"下载前向记录"，或 `GET /api/strategies/<策略>/log`（登录后），一行一条 JSON。
- 验证：`python examples/verify_log.py <文件>`，打印链的最后一环。
- 把最后一环发给别人或存到别处；以后再导出时用 `verify_log.py <文件> <那一环>` 检查它还在链上，就说明那之前的记录没被改过（包括部署这台服务器的人）。

这证明的是"信号是事先发的、发完没改"，不证明策略赚钱。

## 三、回测

见 [backtest.md](backtest.md)。信号表每行"时间,信号"，信号的写法和 Webhook 完全一样，所以回测过的信号表可以原样换成实时发。

例子：[`examples/backtest_ma_cross.py`](examples/backtest_ma_cross.py) 从币安取 1 小时 K 线，均线交叉生成信号表，再用命令行回测。

## 从模拟盘到实盘

1. 在"账户 → 交易所账户"接入币安（[live.md](live.md)），开启下单。
2. 新建一个 Webhook 地址，绑这个交易所账户；或者把原来的地址删掉重建。
3. 先用很小的资金桶跑。每一笔的成交和原因都在信号记录和复盘里，和模拟盘的对照着看。

模拟盘默认按你到币安的实测网络延迟成交；想看服务器放在东京的效果，在"交易偏好 → 模拟下单延迟"里选东京。
